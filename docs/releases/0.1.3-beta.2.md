# WinSTT 0.1.3-beta.2 — Promptable ASR and file speaker identification

October 30, 2026. This second beta covers the changes since v0.1.3-beta.1. It adds an optional instruction-following speech model, keeps lightweight live transcription, and separates file transcription from dictation cleanup.

## Optional Nemotron Transcribe

- Added NVIDIA Nemotron 3.5 Transcribe 30B-A4B as an optional CPU IQ4 model. The existing Nemotron 3.5 Streaming 0.6B models remain available and are not replaced.
- The new model accepts direct audio instructions for transcription, cleanup, and translation. Instructions are separate from context hints and are bound to the selected model, so switching models cannot accidentally carry a cleanup instruction into a context-only model.
- Reuse the cleanup presets, levels, and enabled custom modifiers from Processing as ASR instructions. The prompt requests the resulting text directly, without the text cleanup model's JSON response contract.
- With native ASR cleanup active, dictation skips the separate text cleanup model by default. Running both requires an explicit warning-dialog confirmation. Cleanup suppression depends on a successful instructed decode from the actual speech model, not just the selected settings.
- Processing presets remain editable without configuring Ollama or another cleanup model. Application profiles can supply presets to native ASR without requiring an unrelated text model or provider key.
- Granite Speech 4.1 2B Plus accepts its supported task instructions, such as speaker-attributed transcription and keyword biasing. It is not classified as a general cleanup model, does not consume cleanup presets, and does not suppress the separate cleanup pass. Whisper context hints retain their existing meaning.

## Live preview and native-process reliability

- A final-only main model can use the selected lightweight native-streaming model in its own supervised worker for live preview. The preview maintains decoder state while recording and resets between recordings.
- Preview precision is independent of the main model's IQ4 precision. Changing the preview selection does not reload the resident speech LLM or overwrite the main model's device and quantization settings.
- Preview failure, idle unloading, focus changes, and shutdown are handled independently. Provisional text from a final-only model's preview is not pasted word by word; delivery waits for the main model's final result.
- The Nemotron CPU runtime stays resident inside the supervised inference worker, avoiding a full model reload for every utterance. Its local HTTP endpoint binds to loopback, uses a random authentication token, and bypasses proxies and redirects.
- Worker cancellation, abort, or shutdown terminates native descendants through Windows job objects or Unix process groups, releasing their memory and ports.
- The optional runtime is downloaded from NVIDIA's nightly release when first installed, verified against the published SHA-256 digest, and inventoried locally with its source revision and file hashes. A verified installation is reused offline. Runtime archives reject unsafe paths and external link targets.

## File transcription and speaker exports

- All dropped or picked files, including TXT-only jobs, use the dedicated file decode path. Files do not run the separate dictation cleanup model or dictation's deterministic capitalization and spoken-punctuation formatting.
- Explicit ASR instructions still apply, including cleanup presets when chosen as the speech model's instruction source.
- Added **Identify speakers** and **Speaker prefixes** under Output → File Transcription. Speaker identification currently requires Nemotron Transcribe; unsupported local and cloud paths report an error instead of inventing labels.
- Nemotron processes a file as one recording, up to one hour, preserving the source timeline and a single speaker identity space rather than resetting speakers at voice-activity boundaries.
- Speaker IDs and word timings propagate through inference IPC into transcript segments and exports. Overlapping speakers retain overlapping times and their own words; unassigned words are not attributed to another speaker.
- Optional `Speaker 1:` prefixes appear in TXT, SRT, and copied text. JSON and CSV retain speaker IDs regardless of that preference, JSON words retain their speaker IDs, and VTT uses native voice tags.
- File output choices, including speaker identification and prefixes, are captured when queued. Missing or invalid speaker alignment produces an actionable error instead of fabricated timestamps or identities. Translation or extensive rewriting may require switching to a verbatim ASR prompt for alignment.

## Hardware, packaging, and scope

- The new model's pinned community GGUF conversion downloads approximately 21.35 GB. It uses CPU system RAM on the tested RTX 3080 Ti 12 GB machine; it does not require Blackwell NVFP4 support. Loading checks for at least 24 GiB of available RAM, and 64 GB system RAM is recommended.
- On an i9-12900KF with 64 GB RAM, an 8-second synthetic English clip took about 6–6.5 seconds with a short cleanup instruction or 12–13.4 seconds with the default cleanup presets. Loading took about 21–22 seconds and peak native resident memory was 34.75 GiB. These are short local smoke tests, not multilingual accuracy or long-recording benchmarks.
- A separate 16.9-second two-voice recording returned two consistent speaker IDs with source-timed segments, both with verbatim instructions and with cleanup presets, through the supervised CPU worker. Verified cached weights and runtime also loaded with outbound access disabled.
- Catalog/cache probing now recognizes the required GGUF encoder and decoder together. Hardware-fit routing treats this model as CPU-backed even on CUDA systems. Language detection, supported-language metadata, and model-specific formatting policies were corrected.
- Added regression coverage for prompt routing, cleanup isolation, preview state, native descendants, speaker overlap and alignment failure, export metadata and prefixes, and settings persistence. Local validation includes 5,185 frontend tests, 1,856 Rust unit tests, 11 worker integration tests, browser settings checks, production renderer/docs builds, and lint/type/dead-code checks.
- Windows, Linux x64, and macOS Apple Silicon packages are produced by the release workflow. Windows hardware inference testing does not imply hands-on verification of every device or OS. File diarization remains offline; this release does not add live speaker diarization.
