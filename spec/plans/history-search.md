## 1. Architecture summary

- **Backend (Rust)**: three external-content FTS5 tables (one per history table) kept in sync by SQL triggers (covers every code path including `cleanup.rs` retention deletes). New `history_search` command: sanitized prefix-query MATCH, tiered (strict AND-of-prefixes, then relaxed truncated-prefix OR for typo candidates), kind + date filters, offset pagination, LIKE fallback while backfill is incomplete.
- **Fuzzy layer (client, worker)**: candidates = backend results ∪ in-memory store rows; a new dedicated `history-search.worker.ts` re-ranks with an extended scorer built on `shared/lib/fuzzy-search.ts` and computes highlight ranges. UI thread never scans transcripts.
- **Ranking**: tier 0 exact substring of whole query > tier 1 all-tokens-prefix (bm25 within tier) > tier 2 fuzzy (sum of edit distances); tiebreaker `timestamp DESC`.
- **UI**: search input in the `HistoryTableSection` header (settings tab, primary surface), composing with the existing date-range and kind filters; `<mark>` highlighting in `RowTranscript`; result count; empty state; Ctrl/Cmd+F focus; secondary phase adds the same input to the dedicated history window.

## 2. Backend: schema, migration, backfill

### 2.1 New migration (append to `MIGRATIONS` in `src-tauri/src/managers/history.rs`)

One `M::up` with this batch (tokenizer `unicode61 remove_diacritics 2` matches the frontend normalizer; `prefix='2 3'` accelerates search-as-you-type):

```sql
CREATE VIRTUAL TABLE transcription_fts USING fts5(
    transcription_text, post_processed_text,
    content='transcription_history', content_rowid='id',
    tokenize='unicode61 remove_diacritics 2', prefix='2 3');
CREATE VIRTUAL TABLE transform_fts USING fts5(
    before_text, after_text,
    content='transform_history', content_rowid='id',
    tokenize='unicode61 remove_diacritics 2', prefix='2 3');
CREATE VIRTUAL TABLE tts_fts USING fts5(
    text,
    content='tts_history', content_rowid='id',
    tokenize='unicode61 remove_diacritics 2', prefix='2 3');

CREATE TRIGGER transcription_history_fts_ai AFTER INSERT ON transcription_history BEGIN
    INSERT INTO transcription_fts(rowid, transcription_text, post_processed_text)
    VALUES (new.id, new.transcription_text, coalesce(new.post_processed_text, ''));
END;
CREATE TRIGGER transcription_history_fts_ad AFTER DELETE ON transcription_history BEGIN
    INSERT INTO transcription_fts(transcription_fts, rowid, transcription_text, post_processed_text)
    VALUES ('delete', old.id, old.transcription_text, coalesce(old.post_processed_text, ''));
END;
CREATE TRIGGER transcription_history_fts_au AFTER UPDATE ON transcription_history BEGIN
    INSERT INTO transcription_fts(transcription_fts, rowid, transcription_text, post_processed_text)
    VALUES ('delete', old.id, old.transcription_text, coalesce(old.post_processed_text, ''));
    INSERT INTO transcription_fts(rowid, transcription_text, post_processed_text)
    VALUES (new.id, new.transcription_text, coalesce(new.post_processed_text, ''));
END;
-- (identical ai/ad/au trigger trios for transform_history→transform_fts and tts_history→tts_fts)

-- transform + tts are small (no 5000-row cap pressure): backfill inline here
INSERT INTO transform_fts(rowid, before_text, after_text)
    SELECT id, before_text, after_text FROM transform_history;
INSERT INTO tts_fts(rowid, text) SELECT id, text FROM tts_history;

-- transcription_history may hold ~100k rows: backfill asynchronously (2.2)
CREATE TABLE IF NOT EXISTS search_meta (key TEXT PRIMARY KEY, value INTEGER NOT NULL);
INSERT INTO search_meta(key, value) VALUES
    ('fts_backfill_target', (SELECT coalesce(MAX(id), 0) FROM transcription_history)),
    ('fts_backfill_done_id', 0);
```

Notes: the `coalesce(…, '')` must be applied identically in insert and `'delete'` statements so external-content delete commands reproduce the indexed terms exactly. The UPDATE trigger matters — `post_processed_text` and `llm_meta` are rewritten after insert when the LLM pass completes. Extend the existing `migrations_validate` test; `rusqlite_migration::Migrations::validate()` already runs in debug builds at startup.

### 2.2 Non-blocking backfill

New sibling submodule `src-tauri/src/managers/history/search.rs` (declare `mod search;` in history.rs next to `mod cleanup; mod read; mod write;`):

- `HistoryManager::spawn_fts_backfill(&self)` — called once from `HistoryManager::new` after `init_database()`, via `tauri::async_runtime::spawn_blocking`. Loop: read `fts_backfill_done_id` and `fts_backfill_target`; if done ≥ target, stop. Otherwise one transaction per batch: `INSERT INTO transcription_fts(rowid, transcription_text, post_processed_text) SELECT id, transcription_text, coalesce(post_processed_text,'') FROM transcription_history WHERE id > ?done AND id <= min(?done+1000, ?target) ORDER BY id;` then update `fts_backfill_done_id`. Set `busy_timeout(5000)` on the connection; sleep ~25 ms between batches so dictation writes never starve. New rows past `target` are covered by the triggers, so the backfill converges. ~100k rows completes in a few seconds of background time; startup is never blocked.
- `HistoryManager::fts_ready(conn) -> bool` — `done >= target` (plus a defensive check that `transcription_fts` exists). The search command uses this to pick FTS vs LIKE.

### 2.3 Query building and escaping (also in `search.rs`)

- `fn fts_prefix_query(raw: &str) -> Option<String>`: tokenize on Unicode non-alphanumerics; drop empties; each token emitted as `"token"*` (double any embedded `"`); join with a space (implicit AND). Returns `None` when no tokens survive → caller returns empty result. **Never pass raw user input to MATCH** — bare `AND/OR/NOT/NEAR`, `*`, `:`, `-`, `(` are FTS5 syntax.
- `fn fts_relaxed_query(raw: &str) -> Option<String>`: same tokens, but each token of length ≥ 4 is truncated to `max(3, len - 2)` chars before `"…"*`, joined with ` OR `. This is the cheap typo-candidate net (tail-of-word typos, the common case for dictated text); the worker's edit-distance pass does the precise accept/reject.
- `fn like_pattern(raw: &str) -> String`: escape `\` → `\\`, `%` → `\%`, `_` → `\_`; wrap in `%…%`; used with `… LIKE ?1 ESCAPE '\'`.

### 2.4 New command `history_search` (in `src-tauri/src/winstt/commands/history.rs`)

```rust
#[tauri::command]
#[specta::specta]
pub async fn history_search(
    app: AppHandle,
    webview: WebviewWindow,
    history_manager: State<'_, Arc<HistoryManager>>,
    query: String,
    limit: i64,              // clamp(1, 200)
    offset: i64,             // max(0)
    kinds: Vec<String>,      // subset of ["transcription","transform","tts"]
    date_from: Option<i64>,  // epoch MILLIS (renderer convention); /1000 before use
    date_to: Option<i64>,
) -> Result<HistorySearchResult, String>
```

- Auth: `authorize_history_operation(&webview, HistoryOperation::Read)` (windows `settings`/`history`/`tray-menu` — both surfaces already allowed).
- Runs on `spawn_db` (the existing blocking-pool helper at history.rs line 599).
- Per requested kind, strict-tier SQL (transcription shown; transform/tts analogous):

```sql
SELECT h.id, h.file_name, /* …all existing columns of map_db_row… */, bm25(transcription_fts) AS rank
FROM transcription_fts f JOIN transcription_history h ON h.id = f.rowid
WHERE transcription_fts MATCH ?1
  AND (?2 IS NULL OR h.timestamp >= ?2) AND (?3 IS NULL OR h.timestamp <= ?3)
ORDER BY rank LIMIT ?4 OFFSET ?5
```

- If strict results < limit, run the relaxed query the same way excluding already-returned ids, tag those rows `tier: 2` (strict rows are `tier: 1`; tier 0 is decided client-side by exact-substring check). Over-fetch limit+1 for `hasMore` (the `history_list` pattern).
- If `fts_ready` is false (backfill in flight) or `fts_prefix_query` returns `None` for a non-empty query, fall back to `WHERE h.transcription_text LIKE ?1 ESCAPE '\' OR coalesce(h.post_processed_text,'') LIKE ?1 ESCAPE '\'` ordered by `id DESC`, plain LIKE over 100k short rows is tens of ms; keep `LIMIT ?/OFFSET ?`.
- Response type (specta, camelCase), reusing the existing reshape helpers `to_transcription_entry` / `to_transform_entry` / `to_tts_entry` so rows render with zero new mapping code:

```rust
pub struct HistorySearchResult {
    pub transcriptions: Vec<SearchHit<TranscriptionHistoryEntry>>, // { entry, tier }
    pub transforms: Vec<SearchHit<TransformHistoryEntry>>,
    pub tts: Vec<SearchHit<TtsHistoryEntry>>,
    pub has_more: bool,
    pub fts_active: bool, // false while backfill incomplete (UI may show nothing special; useful for tests)
}
```

(If generic `SearchHit<T>` is awkward under specta, emit three concrete structs.)

- Register in `commands_registry.rs` after line 223. Rebuild regenerates `src/bindings.ts` (`commands.historySearch`).

**Scope decision (requirement 4):** index transcript text only — `transcription_text` + `post_processed_text`, transform `before_text` + `after_text`, tts `text`. Do **not** index `title` (it's a formatted timestamp), `history_tag` (fixed enum — belongs to a future tag filter chip, not text search), or `stt_model`. `privacy_markers_json` must never be searchable.

## 4. Fuzzy layer + ranking + highlights (worker)

### 4.1 Extend the shared matcher — `src/shared/lib/fuzzy-search.ts`

Add (keep `matchesFuzzySearch` untouched) two exported functions in a new sibling `src/shared/lib/fuzzy-score.ts` (or same file):

- `scoreFuzzyMatch(haystack: string, query: string): { tier: 0 | 1 | 2; cost: number } | null` — tier 0: normalized haystack contains the whole normalized query; tier 1: every query token literal-prefix/containment-matches a haystack token (cost 0); tier 2: every token matches with bounded Damerau-Levenshtein (cost = summed distances); `null` = no match. Reuse the module's existing normalize/tokenize/distance internals.
- `computeHighlightRanges(text: string, query: string): Array<{ start: number; end: number }>` — ranges **on the original text** (case-insensitive scan for literal token occurrences; for fuzzy-only tokens, highlight the haystack token that matched). Merge overlaps, sort ascending. Diacritics caveat: scan a lowercased copy of the original (not the NFKD-stripped one) so offsets always align; accept that a query "café"→"cafe" literal miss degrades to token-level highlight.

### 4.2 New worker — `src/widgets/transcription-history-settings/lib/history-search.worker.ts`

Same shape as `history-stats.worker.ts` (typed `WorkerScope`, seq echo). Request: `{ seq, query, items: SerializableItem[] }` where items are `{ key: string ("kind:id"), text: string (effective/display text), timestamp: number, backendTier: 1 | 2 | null }` — union of backend hits and in-memory store rows (deduped by key before posting). Response: `{ seq, matches: Array<{ key, ranges: {start,end}[] }> }` ordered by: min(backendTier, scorer tier) asc → cost asc → timestamp desc. Rows failing `scoreFuzzyMatch` AND lacking a backendTier are dropped.

### 4.3 New hook — `src/widgets/transcription-history-settings/api/use-history-search.ts`

Copy the `use-history-stats.ts` singleton/fallback/seq pattern. Signature:

```ts
useHistorySearch(query: string, combinedEntries: HistoryTableItem[], range: DateRange | null):
  { items: HistoryTableItem[]; highlights: Map<string, Range[]>; loading: boolean; totalLabelCount: number; hasMore: boolean }
```

Flow per (debounced) query change: bump seq → fire `historySearch({ query, limit: 200, offset: 0, kinds: all, dateFrom, dateTo })` and, in parallel, prepare in-memory items → on IPC resolve, post the merged candidate set to the worker → on worker resolve, drop if seq stale, else set state. Empty/whitespace query short-circuits to passthrough (no IPC, no worker). Queries shorter than 2 chars: skip the IPC call, worker-only over in-memory rows. Worker construction failure degrades to synchronous main-thread scoring (same fallback contract as stats). Backend rows not present in the store are materialized into `HistoryTableItem`s from the response (this is what makes search reach past the 5000-row `history_get_all` cap).

## 6. Performance requirements mapping

- 100k rows: FTS5 prefix index (`prefix='2 3'`) makes strict-tier MATCH milliseconds-fast; relaxed tier is bounded by `LIMIT`; LIKE only during first-run backfill.
- UI thread: all scoring/edit-distance/highlight computation in `history-search.worker.ts`; IPC + worker both seq-guarded so stale responses are dropped (cancellation requirement — Tauri invokes can't be aborted, dropping is the established pattern here).
- Typing: 150 ms debounce; per-keystroke work on the UI thread is just state set + (already-virtualized) `VList` render of ≤200 rows.
- Backfill: batched (1000/txn) background task, `busy_timeout`, inter-batch sleep.
